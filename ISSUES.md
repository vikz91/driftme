# Issue Guidelines

GitHub Issues are used to track bugs, discuss improvements, and clarify behavior.

Please keep issues focused and respectful.

---

## When to Open an Issue

Open an issue for:
- Bugs or unexpected behavior
- UI or UX problems
- Clarification questions
- Feature proposals (discussion only)

---

## Before Opening an Issue

- Search existing issues
- Make sure the issue is reproducible or clearly explained
- Keep scope narrow

Low-effort or vague issues may be closed.

---

## Feature Proposals

Feature requests must:
- Align with Drift’s philosophy
- Reduce cognitive load
- Preserve calm and simplicity

Proposals that add pressure, metrics, or complexity will be declined.

---

## Bug Reports

Include:
- What you expected to happen
- What actually happened
- Steps to reproduce
- Screenshots or logs if relevant

---

## Not Supported

Issues are **not** for:
- Personal productivity advice
- Feature demands
- Monetization discussions
- Support guarantees

Drift is provided as-is.
