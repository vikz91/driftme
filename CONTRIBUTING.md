# Contributing to Drift

Thank you for your interest in contributing to Drift.

Drift is a personal, reflective tool with a strong philosophy.  
Contributions are welcome, but **scope discipline matters more than feature velocity**.

---

## Before You Contribute

Please read:
- `PROJECT.md` — to understand what Drift is and is not

If a change conflicts with Drift’s philosophy, it will not be accepted.

---

## What to Contribute

Good contributions include:
- Bug fixes
- Performance improvements
- Accessibility fixes
- UI polish and consistency
- Documentation improvements
- Refactoring for clarity

Feature additions must be discussed **before** implementation.

---

## What Not to Contribute

Drift does not accept:
- Gamification features
- Social or collaborative features
- Time tracking or productivity metrics
- Heavy configuration systems
- Features that increase cognitive load

---

## How to Contribute

1. Fork the repository
2. Create a focused branch
3. Keep changes small and scoped
4. Follow existing code style and structure
5. Open a pull request with a clear description

---

## Pull Request Guidelines

- One logical change per PR
- Clear explanation of *why*, not just *what*
- Screenshots for UI changes
- PRs may be closed if they do not align with philosophy

---

## Governance

Drift follows a **BDFL (Benevolent Dictator For Life)** model.

Final decisions rest with the project owner to preserve long-term clarity and direction.

---

## Code of Conduct

Be respectful.  
Assume good intent.  
Keep discussions technical and calm.
